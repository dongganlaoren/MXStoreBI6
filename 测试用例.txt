# 成本统计功能测试用例
# 生成时间：2025年9月3日
# 测试目标：验证报表中心-成本统计功能的计算准确性

## 最新更新 (2025-09-03)
### Bug修复：分摊金额计算错误
**问题描述**：分摊金额计算时包含了不存在的店铺ID，导致分摊金额被稀释
**修复方案**：
- 在按店铺聚合报销金额的查询中添加与Store表的JOIN
- 确保只统计存在于Store表中的店铺数据
- 修复后分摊计算更加准确

### Bug修复：总成本合计计算错误
**问题描述**：总成本合计与分类汇总金额不一致
**修复方案**：
- 为所有报销查询添加与Store表的JOIN操作
- 确保所有统计都基于存在于Store表中的店铺数据
- 修复后总成本合计与分类汇总金额完全一致

### Bug修复：公摊成本计算丢失
**问题描述**：公摊成本在统计中丢失或计算错误
**修复方案**：
- 添加详细的调试日志来跟踪公摊成本的计算过程
- 验证公摊成本查询条件是否正确
- 检查数据筛选和JOIN操作是否正常工作
- 确保公摊成本正确分摊到各店铺

### 功能改进：总成本计算和统计列
**改进内容**：
- 总成本合计现在包括公摊成本：总成本 = 各店铺实际成本 + 公摊成本
- 在表格中添加统计行，显示各列的总计
- 优化数据显示的一致性

### Bug修复：字段名错误
**问题描述**：代码中使用 `ReimbursementRequest.id` 但实际字段名是 `request_id`
**修复方案**：
- 将所有 `ReimbursementRequest.id` 替换为 `ReimbursementRequest.request_id`
- 修复了两个查询中的字段名错误

### 2. 预期计算结果

#### 基本统计（8月数据）：
- **店铺A总成本**：1500 + 800 + 1200 = 3500.00
- **店铺B总成本**：2000 + 600 = 2600.00
- **店铺C总成本**：1800.00
- **总成本合计**：3500 + 2600 + 1800 + 5500（公摊） = 12400.00（包括公摊成本）
- **各店铺实际成本总和**：3500 + 2600 + 1800 = 7900.00

#### 公摊成本计算：
- **公摊总额**：3000 + 2500 = 5500.00
- **分摊到店铺数量**：3个店铺
- **每店分摊金额**：5500 ÷ 3 = 1833.33

#### 分摊后成本：
- **店铺A分摊后成本**：3500 + 1833.33 = 5333.33
- **店铺B分摊后成本**：2600 + 1833.33 = 4433.33
- **店铺C分摊后成本**：1800 + 1833.33 = 3633.33
- **分摊后总成本**：5333.33 + 4433.33 + 3633.33 = 13400.00

#### 分类汇总：
- **固定工资**：1500 (A) + 2000 (B) + 1800 (C) = 5300.00
- **水电费**：800 (A) = 800.00
- **物料运输**：1200 (A) = 1200.00
- **店铺备用金**：600 (B) = 600.00
- **代理记账**：3000 (公摊) = 3000.00
- **员工社保**：2500 (公摊) = 2500.00

#### 预期计算结果验证点：
- **总成本合计**：应等于各店铺实际成本总和 + 公摊成本总和
- **表格统计行**：显示各列的总计数据
- **数据一致性**：所有统计查询都基于相同的条件（APPROVED + CHECKED + 存在店铺）
- **分摊计算**：基于实际存在的店铺数量进行均等分摊

## 常见问题排查

1. **数据不显示**：
   - 检查报销记录的状态是否为 APPROVED
   - 检查 check_status 是否为 CHECKED
   - 检查 approved_at 是否在查询时间范围内

2. **分摊计算错误**：
   - 确认公摊成本的 primary_category 为 SHARED_COST
   - 确认所有店铺都有对应的报销记录（即使金额为0）

3. **分类汇总错误**：
   - 检查 secondary_category 字段是否正确设置
   - 确认分类汇总只统计符合条件的记录
