店铺整改模块功能设计（修改版）

1. 核心功能概述
店铺整改模块是一个用于管理店铺问题发现、整改任务分配、执行跟踪和验收的流程管理系统。

2. 主要功能模块

2.1 整改任务管理
- **整改任务创建**：管理员/总店长可以创建整改任务
- **任务分类**：按照问题类型分类（卫生问题、设备维护、服务质量、安全隐患等）
- **优先级设置**：紧急、高、中、低四个优先级
- **任务分配**：指定责任店铺，系统自动分配给该店铺的店长
- **截止时间管理**：设置整改完成期限

2.2 整改流程控制
- **任务状态流转**：
  - 待处理 → 处理中 → 待验收 → 已完成 → 已关闭
  - 可设置驳回状态：验收不通过 → 重新整改
- **简化审批**：无多级审批流程，直接由责任店长处理
- **自动提醒**：临近截止时间自动提醒相关人员

2.3 问题记录与跟踪
- **问题描述**：详细记录发现的问题
- **现场图片/视频**：支持上传问题现场的图片和视频证据
- **整改前后对比**：记录整改前后的状态对比
- **完成状态更新**：责任人更新任务完成状态

2.4 整改验收管理
- **验收人员**：默认为总店长进行验收
- **验收结果记录**：通过/不通过，及验收意见
- **复查机制**：对于不通过的整改进行复查

2.5 统计分析功能
- **整改统计报表**：
  - 按店铺统计整改任务数量和完成率
  - 按问题类型统计分析
  - 按时间维度统计趋势
- **效率分析**：整改平均用时、逾期率分析
- **排行榜**：店铺整改效率排名

3. 数据模型设计要点

3.1 整改任务表 (renovation_tasks)
- 任务ID、标题、描述、问题类型、优先级
- 关联店铺ID、创建人、负责人（默认店长）、验收人（默认总店长）
- 状态、创建时间、计划完成时间、实际完成时间

3.2 整改分类表 (renovation_categories)
- 分类ID、分类名称、父分类ID（支持多级分类）
- 分类描述、排序权重

3.3 整改记录表 (renovation_records)
- 记录ID、任务ID、操作类型、操作内容
- 操作人、操作时间、附件信息

3.4 整改附件表 (renovation_attachments)
- 附件ID、任务ID、文件类型、文件路径
- 上传人、上传时间、文件描述

4. 用户角色权限

4.1 管理员/总店长
- 创建整改任务
- 查看所有店铺的整改情况
- 验收所有整改任务
- 统计分析和报表查看
- 系统配置管理

4.2 分店长/店员（功能一致）
- 查看本店铺的整改任务
- 更新任务状态（处理中/已完成）
- 上传整改证据
- 提交验收申请

5. 系统通知模块（独立设计）

5.1 通知类型枚举
- 整改任务分配通知
- 逾期预警通知
- 验收通知
- 结果通知
- 其他模块通知（预留扩展）

5.2 通知配置表 (notification_config)
- 配置ID、通知类型、模块名称
- 接收人规则、发送渠道（邮件/站内信/推送）
- 通知模板、启用状态

5.3 通知任务表 (notification_tasks)
- 任务ID、通知类型、关联对象ID、关联模块
- 接收人列表、发送状态、发送时间
- 重试次数、错误信息

5.4 通知模板表 (notification_templates)
- 模板ID、通知类型、语言（zh/th）
- 标题模板、内容模板、创建时间

5.5 通知提醒机制
- **任务分配通知**：新任务分配时通知责任店长
- **逾期预警**：临近截止时间提醒
- **验收通知**：任务完成后通知总店长
- **结果通知**：验收结果通知相关人员

7. 移动端支持
- **响应式设计**：支持手机、平板访问
- **拍照上传**：现场拍照直接上传
- **扫码功能**：通过二维码快速访问任务详情
- **推送通知**：重要状态变更推送到移动设备

8. 与现有模块的集成
- **用户权限集成**：复用现有的用户角色体系
- **店铺信息集成**：关联现有的店铺管理数据
- **附件管理集成**：复用现有的文件上传功能
- **通知系统集成**：集成独立设计的系统通知模块

9. 简化后的业务流程
1. 管理员/总店长创建整改任务 → 系统自动分配给目标店铺的店长
2. 店长接收通知 → 开始处理任务 → 上传整改证据 → 标记为已完成
3. 系统通知总店长进行验收 → 总店长验收（通过/不通过）
4. 验收结果通知相关人员 → 任务关闭或重新整改
