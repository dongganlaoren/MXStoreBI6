# 关于“app\templates\sales\check_edit.html”页面的功能改进

## 背景：财务人员或者管理员往往因为某种原因，在核对营业数据时，需要对上报的数据进行修改，但为了数据安全性及可溯源性需要对修改的过程进行记录，以便在出现问题时可以找到原因。

1. **修改痕迹与历史记录**

   每次用户修改关键字段（cash_income、pos_income、takeaway_amount、electronic_actual_arrival、bank_deposit、bank_fee）时（其它字段不可修改），自动保存一条修改历史（可建一张如bank_deposit_history表，记录字段名、原值、新值、修改人、时间、备注等）。审核页面可展示“修改历史”tab或列表，便于追溯。

2. **前端交互**

   可在字段旁增加“修改”按钮，弹窗或直接切换为可编辑状态，修改后需填写原因或备注。修改后高亮显示，提示“已修改，待保存”。

3. **数据一致性**

   后端保存时，自动重新计算相关联的自动计算字段（如误差、实际总营业额等），确保数据一致。

4. **操作日志**

   重要字段变更时，写入操作日志（如：谁在什么时间将某字段从X改为Y，理由/备注）。
