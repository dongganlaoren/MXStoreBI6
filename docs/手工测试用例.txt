# 手工测试用例（MXStoreBI）

说明
- 目的：覆盖系统核心流程与关键边界，作为每次发版前的人工回归清单。
- 适用范围：当前代码主干（已移除监控模块），测试/生产环境皆可（部分步骤注记差异）。
- 约定：
  - 管理员账号：admin / secret123
  - 普通员工账号：emp / pw（如未存在，请先在管理端创建或通过注册创建）
  - 浏览器建议使用隐身模式，避免会话残留影响结果。

测试环境准备
1) 数据库迁移
   - 执行 flask db upgrade，确保最新迁移（含删除监控表的迁移）已应用。
2) 依赖与启动
   - pip install -r requirements.txt
   - flask run 或 supervisor 启动项目。
3) 可选：初始化基础数据（如门店）以便首页展示。

通用检查项（每轮回归前简要执行）
- 顶部导航与菜单显示是否与角色一致（管理员/员工）。
- 语言切换参数 ?lang=zh / ?lang=th 生效，页面主要文案随之变化。
- 未登录访问需要登录的页面是否被重定向至登录页。
- 文件下载仅限授权用户，越权访问返回 404/无权限提示。

用例清单

AUTH-001 登录成功（管理员）
- 前置：存在管理员 admin/secret123。
- 步骤：访问 /login，输入用户名 admin 密码 secret123，勾选“记住我”。
- 期望：登录成功跳转首页，右上角显示 admin；会话保持，后续访问“/”返回 200（见 ROOT-001）。

AUTH-002 登录失败
- 步骤：/login 输入错误密码。
- 期望：提示“用户名或密码无效”，停留登录页，状态码 200。

AUTH-003 注册新用户（员工）
- 步骤：/register 按表单要求填写（员工角色可选门店），提交。
- 期望：注册成功并自动登录，跳转首页可见该用户信息。

AUTH-004 登出
- 步骤：右上角菜单选择“退出登录”。
- 期望：提示登出成功，随后访问需要登录的页面会被重定向。

ROOT-001 根路径（已登录-记住我）
- 前置：以“记住我”登录（AUTH-001）。
- 步骤：直接访问“/”。
- 期望：直接渲染 main.index，状态码 200。

ROOT-002 根路径（已登录-未记住我）
- 前置：以未勾选“记住我”登录。
- 步骤：访问“/”。
- 期望：302 重定向到 /home（main.index）。

ROOT-003 根路径（未登录）
- 步骤：退出登录后访问“/”。
- 期望：302 重定向到 /login。

MAIN-001 首页渲染（管理员，有门店）
- 前置：至少存在 1 家门店，可选存在本月日报记录。
- 步骤：管理员登录访问“/”。
- 期望：门店列表渲染成功；若有日报，展示本月累计与近 7 天数据。

MAIN-002 首页渲染（员工，仅本店）
- 前置：员工账号绑定 store_id。
- 步骤：员工登录访问“/”。
- 期望：仅看到自己门店数据；无门店则页面无门店信息或显示“暂无门店”。

MAIN-003 周数据断续展示
- 前置：某门店近 7 天有零散日报（非连续）。
- 步骤：管理员登录访问首页。
- 期望：近 7 条按日期逆序补齐显示，无数据的日期项显示 0 或占位。

USER-001 个人资料查看
- 步骤：登录后访问 /profile。
- 期望：显示当前登录用户信息。

USER-002 个人资料编辑（门店组一次性完善）
- 前置：门店组用户（EMPLOYEE/BRANCH_MANAGER），未完善档案。
- 步骤：访问 /profile/edit 填写保存。
- 期望：保存成功并标记已完善；再次进入编辑页提示不可修改。

USER-003 管理员重置用户密码
- 前置：管理员登录，存在目标用户。
- 步骤：在“用户管理”列表点击“重置密码”。
- 期望：接口返回 200；目标用户密码重置为 123456。

USER-004 身份证复印件下载（本人）
- 步骤：登录用户访问 /download_id_card_copy。
- 期望：若未上传返回 404；上传后可在线预览/下载。

ADMIN-001 用户管理列表
- 步骤：管理员登录进入“系统管理-用户管理”。
- 期望：列表可加载，支持分页/搜索（若实现）。

ADMIN-002 非管理员访问管理员页面
- 步骤：员工角色访问 /admin/users/。
- 期望：被拦截（重定向或无权限提示），状态码 200 且页面无敏感数据。

SALES-001 营业管理列表
- 步骤：登录后访问营业管理列表页。
- 期望：页面渲染成功，数据正常分页。

SALES-002 附件上传/下载
- 步骤：在营业/日报相关页面上传允许类型的附件，保存后从页面下载。
- 期望：上传成功；下载链接仅对授权用户可用，文件内容正确。

SALES-003 员工越权访问他店数据
- 前置：员工 A 绑定门店 A。
- 步骤：尝试通过 URL 参数访问门店 B 的记录。
- 期望：无权访问或数据不可见。

REIM-001 提交报销申请
- 步骤：进入报销申请页面，填写合法金额与说明，提交。
- 期望：保存成功，列表出现新记录。

REIM-002 报销附件上传/下载
- 步骤：新增/编辑时上传附件，保存后在详情中下载。
- 期望：上传与下载成功；非提交者/审批者不可下载敏感附件。

REIM-003 审批流程（如有）
- 前置：存在需要审批的报销。
- 步骤：以审批角色登录，审批通过/驳回。
- 期望：状态流转正确，记录日志。

EMAIL-001 邮件设置页
- 步骤：管理员进入“系统管理-邮件设置”。
- 期望：页面可打开；保存配置项（若有）成功。

EMAIL-002 邮件发送日志
- 步骤：访问 /email_report/log_list。
- 期望：日志列表正常展示；必要字段完整。

NEG-001 未授权下载
- 步骤：未登录或无权限用户访问他人附件下载链接。
- 期望：返回 404 或无权限提示。

NEG-002 404 页面
- 步骤：访问不存在的 URL。
- 期望：返回自定义 404 页面。

NEG-003 防路径穿越
- 步骤：在下载接口尝试通过 path 参数传入 .. 或绝对路径（若接口暴露）。
- 期望：服务端拒绝，返回 400/404；无任意文件读取风险。

LANG-001 语言切换
- 步骤：在任意页面追加 ?lang=th / ?lang=zh。
- 期望：文案语言切换生效；后续页面沿用选择（session）。

MON-REMOVED 监控模块已移除回归检查
- 步骤：检查导航“系统监控”入口是否消失；访问 /monitor 或相关 API。
- 期望：无入口；访问 /monitor 返回 404。

DEPLOY-001 CI 质量门禁
- 步骤：向 main 分支推送代码。
- 期望：GitHub Actions 先运行 pytest；仅当测试通过时才执行部署步骤。

MIG-001 监控表清理迁移
- 步骤：检查数据库中是否仍存在 system_logs/system_alerts/system_metrics/health_checks。
- 期望：迁移后上述表已删除；PostgreSQL 场景相关枚举类型已清理。

附录：常用命令
- 运行测试：pytest -q
- 数据库迁移：
  - 生成：flask db migrate -m "msg"
  - 升级：flask db upgrade
- 本地启动：flask run（或通过 Supervisor）

执行建议
- 在“无痕窗口”分别验证“记住我”和“未记住我”的根路径行为，避免 cookie 干扰。
- 重点关注权限边界（员工/管理员）、文件下载、语言切换、登录态与重定向逻辑。
